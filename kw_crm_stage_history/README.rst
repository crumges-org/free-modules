Automatic tracking of CRM lead and opportunity stage changes. Every time a
lead moves from one stage to another, a history record is created with
timestamps, the user who made the change, and computed duration metrics.

This module uses ``generic_mixin`` to track ``stage_id`` field changes via
``@post_create`` and ``@post_write`` decorators, ensuring reliable and
non-intrusive stage change detection.

Configuration
=============

Security Groups
---------------

The module defines a custom security group:

- **CRM Stage History Viewer** (under Sales category) -- grants read-only
  access to stage history records and makes the "Stage Change History" tab
  visible on lead/opportunity forms.

Sales Managers automatically have full read/write/create/delete access to
stage history records.

To grant a user read-only access to stage history, add them to the
**CRM Stage History Viewer** group via **Settings > Users & Companies > Users**.

Usage
=====

Once installed, the module works automatically. No manual action is required
to start tracking stage changes.

Lead/Opportunity Form
---------------------

A new **Stage Change History** tab is added to the lead/opportunity form
(visible to users in the *CRM Stage History Viewer* group or *Sales Manager*
group). The tab displays a read-only list of all stage transitions with:

- Previous stage and new stage
- Date and user who moved the lead into the stage
- Date and user when the lead left the stage
- Duration in days, hours, and total hours

Stage Change Analysis
---------------------

A dedicated menu item **CRM > Stage Change Analysis** provides access to all
stage history records across all leads. Available views:

- **List view** -- all stage transitions with full details
- **Form view** -- detailed view of a single transition record
- **Pivot view** -- aggregated analysis with stage as rows and duration
  metrics (days, hours, total hours) as measures

The search view supports filtering and grouping by lead, source stage, target
stage, and the user who performed the change.

Models
======

kw.crm.stage.history
---------------------

Stores individual stage transition records.

Fields:

- ``lead_id`` (Many2one to ``crm.lead``) -- the lead or opportunity
- ``stage_from_id`` (Many2one to ``crm.stage``) -- the previous stage
  (empty for newly created leads)
- ``stage_to_id`` (Many2one to ``crm.stage``) -- the new stage
- ``date_in`` (Datetime) -- when the lead entered this stage
- ``date_in_by_id`` (Many2one to ``res.users``) -- user who moved the lead
  into this stage
- ``date_out`` (Datetime) -- when the lead left this stage
- ``date_out_by_id`` (Many2one to ``res.users``) -- user who moved the lead
  out of this stage
- ``day_diff`` (Integer, computed, stored) -- number of full days spent in
  the stage
- ``time_diff`` (Float, computed, stored) -- remaining hours beyond full days
- ``total_time_diff`` (Float, computed, stored) -- total duration in hours

crm.lead (inherited)
---------------------

Extends the standard ``crm.lead`` model with:

- ``kw_stage_history_ids`` (One2many to ``kw.crm.stage.history``) -- all
  stage transition records for the lead
- Inherits ``generic.mixin.track.changes`` to detect ``stage_id`` changes
  via ``@post_create`` and ``@post_write`` decorators

Dependencies
============

- ``crm`` -- standard Odoo CRM module
- ``generic_mixin`` -- provides the ``generic.mixin.track.changes`` mixin
  for reliable field change tracking

Known issues / Roadmap
======================

- Stage history records are created automatically and cannot be manually
  edited by non-manager users (read-only access for viewers).
- The ``stage_from_id`` field is empty for the initial stage history record
  created when a lead is first created.
